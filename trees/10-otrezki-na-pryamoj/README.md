# G. Отрезки на прямой

`2 с` · `256 МБ` · 3 балла · [решение](solution.cpp)

В этой задаче нет ограничений на используемые структуры данных.

Улица представляет собой длинный отрезок, изначально разбитый на отрезки, пересекающиеся только по границам, например $[1, 18] = [1, 4] \cup [4, 9] \cup [9, 14] \cup [14, 18]$. Отрезки пронумерованы слева направо, начиная с $1$.

Обработайте $q$ запросов двух видов:

- `1 i` - удалить $i$-й отрезок и распределить его содержимое между соседями;
- `2 i` - разбить $i$-й отрезок на два.

Если отрезок имел длину $2k$, то после разбиения на его месте появляется два отрезка длины $k$. Если длина была $2k + 1$, появляются отрезки длины $k$ и $k + 1$ именно в таком порядке слева направо.

При удалении отрезка: если сосед был только один, всё содержимое переходит в него. Если соседей было двое, исходный отрезок сначала разбивается на два (тем же образом), а затем обе части присоединяются к ближайшему соседнему отрезку.

Нумерация отрезков изменяется после выполнения очередного запроса. Гарантируется, что длины всех отрезков никогда не станут меньше $2$, а к единственному оставшемуся отрезку не будет применён запрос типа $1$.

Для каждого $i$ от $0$ до $q$ сообщите сумму квадратов длин всех отрезков после применения первых $i$ запросов.

## Формат ввода

Первая строка содержит одно целое число $n$ ($2 \le n \le 10^5$) - исходное количество отрезков.

Вторая строка содержит $n$ целых чисел $a_1, a_2, \ldots, a_n$ ($2 \le a_i \le 10^4$) - длины исходных отрезков слева направо.

Третья строка содержит одно целое число $q$ ($1 \le q \le 10^5$) - количество запросов.

Следующие $q$ строк описывают запросы. Гарантируется, что все запросы корректны.

## Формат вывода

Для каждого $i$ от $0$ до $q$ выведите сумму квадратов длин всех отрезков после применения первых $i$ запросов.

## Решение

Декартово дерево по неявному ключу здесь не подходит: обращение идёт и по номеру отрезка, и по его левой границе. Поэтому ключом служит координата начала отрезка, а само дерево - обычный треап со `split` / `merge`. В узле хранятся длина отрезка, размер поддерева и сумма квадратов длин поддерева; сумма и размер пересчитываются в `Update` после каждой склейки.

Ответ на запрос - сумма квадратов в корне, то есть $O(1)$ после каждой операции. Номер отрезка переводится в его координату порядковой статистикой `Kth` по размерам поддеревьев, соседи находятся спусками `Next` и `Prev`.

Обе операции выражаются через удаление и вставку двух-трёх отрезков: разбиение заменяет отрезок на две половины, удаление отдаёт содержимое единственному соседу или делит его между двумя. Приоритеты берутся из заранее перемешанной перестановки, поэтому дерево остаётся сбалансированным по вероятности.

Итого $O((n + q)\log n)$.
